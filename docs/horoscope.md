# Личный гороскоп

В «Людях» у каждого активного человека можно выбрать один из 12 знаков или
«Не указан». Также можно указать необязательную полную дату рождения. Выбор
связан с постоянным ID человека, а не телефоном или именем. Переименование сохраняет знак; объединение входящего человека с
человеком дома сохраняет профиль человека дома.

Если ручной знак указан, он имеет приоритет. Если ручной знак пуст и есть дата
рождения — знак определяется календарными границами, без внешнего запроса.
Пункт «По дате рождения» возвращает автоматический расчёт. Ручное уточнение
полезно для пограничных дат. При удалении даты ручной знак сохраняется.

В профиле показывается возраст в полных годах: он вычисляется при чтении,
не сохраняется числом и меняется в день рождения по часовому поясу хаба
(`HUB_HOROSCOPE_TIMEZONE`). Для родившихся 29 февраля возраст в невисокосный
год меняется 1 марта. Будущие/невозможные даты отклоняются. Миграция nullable
колонки birth_date сохраняет всех людей, лица, персонажей и прежние знаки.
Дата не входит в синхронизацию лиц или ответ гороскопа и остаётся в хабе.
Сами по себе возраст и дата рождения не определяют обучение в школе или
пенсионный статус: такие сценарии ещё не реализованы.

В «Интеграциях» выбирается источник гороскопа. По умолчанию включена Europa Plus,
ключ не требуется. Пустой источник выключает функцию без удаления знаков.

После «Зюзя» скажите «гороскоп», «расскажи мой гороскоп» или
«прочитай гороскоп на сегодня». Нужны Androsaur 0.7 (versionCode 13) и
androsaur-audio 0.5 (versionCode 5). Главное приложение дожидается узнавания,
запрашивает актуальный знак и прогноз, проверяет, что человек не сменился,
и передаёт текст синтезатору звука. Завтрашний гороскоп пока не поддерживается:
ассистент сообщает об этом, а не читает сегодняшний за завтра.

## Контракт и замена источника

`app/horoscope.py`: канонические ID знаков (`aries` … `pisces`),
`HoroscopeProvider.today(day) -> DailyHoroscopes` и ответ телефону.
Провайдер возвращает прогнозы всех 12 знаков на запрошенный день и признак
`source_date_verified`. Сетевые ошибки и неполный ответ превращаются в
`HoroscopeError`. Сервис не знает формат внешнего сайта, телефон не знает
провайдера и его коды знаков.

Для нового источника:

1. Реализовать адаптер в `app/clients/`, переводящий собственные ID в `SIGNS`.
2. Зарегистрировать `HoroscopeSource(название, фабрика, speech_name)` в `PROVIDERS`
   сервиса гороскопа. `speech_name` — произносимое русским голосом название;
   например, у `Europa Plus` это «радио Европа Плюс». Если оно не указано,
   используется отображаемое название. Так телефон не знает названий провайдеров.
   При необходимости фабрика получает настройки/ключ из интеграций хаба.
3. Добавить тесты адаптера на валидные данные, даты и повреждённые ответы.

Источник появляется в списке автоматически. Менять БД профилей, API телефона
и распознавание команды не требуется. Подмена источника проверяется тестом с
двумя разными фабриками; производственный адаптер пока один.

Europa Plus запрашивается по
`https://admin.europaplus.ru/api/horoscope?region=85` (Санкт-Петербург).
Берутся `data.type[*].code` и `today`; например, нестандартный код `rozeyrog`
преобразуется в канонический `capricorn`. Имена и знаки конкретных людей на
сторонний сайт не отправляются: один запрос получает все знаки.

Источник **не сообщает дату публикации**. Адаптер помечает прогноз днём
получения и оставляет `source_date_verified=false`; он не может обнаружить
случай, когда сам сайт продолжает отдавать вчерашний текст. Это внутренний API
сайта, его формат может измениться. Неполные ответы, HTML и пустые тексты
не заменяют хороший кэш.

## Кэш и календарь

`HUB_HOROSCOPE_TIMEZONE` (по умолчанию `Europe/Moscow`) задаёт день, независимо
от часового пояса ОС сервера. Хаб сохраняет полный пакет на диск по
`provider + day` и обновляет по запросу не чаще раза в час. Параллельные запросы
пользователей/телефонов разделяют одну загрузку. После сетевой ошибки повтор
не раньше чем через минуту. При сбое можно прочесть только кэш текущего дня.
На следующий день прежний пакет не используется.

Телефон каждый раз обращается к хабу, поэтому смена знака/источника видна сразу.
Успешный ответ сохраняется в приватных настройках по адресу хаба + person ID.
При потере связи можно читать его до `valid_until_ms` (следующая полночь хаба),
включая перезапуск приложения. При переводе часов назад до времени получения
кэш не используется. Ответ хаба «знак не указан»/«выключено»/другая ошибка
удаляет местную копию этого человека. Недоступный хаб не мешает другим функциям.
Без связи телефон знает последние полученные настройки, поэтому удалённое
выключение источника или смена знака узнаются при восстановлении связи.

## API

`POST /api/horoscope`, тело `{"person":"<постоянный ID>"}`. Ответ JSON,
`Cache-Control: no-store`:

```json
{
  "status": "ok",
  "person": "example-person",
  "date": "2026-11-06",
  "timezone": "Europe/Moscow",
  "valid_until_ms": 1793998800000,
  "sign": "aries",
  "sign_name": "Овен",
  "text": "Текст прогноза",
  "source": "europaplus",
  "source_name": "Europa Plus",
  "source_speech_name": "радио Европа Плюс",
  "fetched_at_ms": 1793944800000,
  "source_date_verified": false
}
```

Управляемые состояния: `unknown_person`, `sign_missing`, `disabled`,
`unavailable` (текст отсутствует). Звуковой модуль публикует событие
`command` с `intent=horoscope`, `tomorrow` и `personId`; к хабу ходит только
главное приложение.

Проверки: `make check`; тесты покрывают смену знака/источника, отключение,
кэш, сбой, границу суток, часовой пояс, параллельные запросы, миграцию старой
БД, переименование/объединение и разбор ответа Europa Plus.
