# CLAUDE.md

Гайд для Claude Code (и других агентов) при работе в этом репозитории.

## Что это

Хаб Androsaur: домашний сервер с админкой для телефонов-ассистентов. **FastAPI + Jinja2 +
SQLite**, слоистая архитектура (выросла из шаблона портала). Контекст продукта и решения
владельца — `androsaur-brief.md` и `projects/androsaur-hub/PROJECT_BRIEF.md` в пространстве
Androsaur.

- К хабу подключается только главное приложение `androsaur`, по одному на телефон; модули
  звука и камеры к серверу не ходят. Телефон автономен: без хаба он работает на последних
  полученных настройках.
- Настройки описывает сам телефон (`POST /api/device/register` со схемой), хаб хранит
  значения уровня дома и номер ревизии. Телефон раз в 30 с вызывает `POST /api/device/sync`:
  сообщает применённую ревизию, имена людей камеры и результаты команд, получает настройки и
  невыполненные команды (пока одна — `rename_person`).
- Телефон ходит к хабу по домашнему Wi‑Fi (`http://<адрес хаба>:8770`), хаб слушает
  `0.0.0.0`. Входа в админку и проверки устройства пока нет: менять настройки может любой в
  домашней сети. Вход, токены устройств и подключение по QR — следующие шаги.
- Репозиторий публичный: голоса, векторы лиц и база (`data/`) в git и логи не попадают.

## Архитектура

Поток запроса строго однонаправленный:

```
router (HTTP / HTML)  →  service (бизнес-логика)  →  repository (SQL)  →  SQLite
```

Правила слоёв:

- **routers/** (`pages.py`, `api.py`) — разбор запроса, вызов сервиса, формирование
  ответа (HTML или JSON). Здесь нет SQL и бизнес-правил.
- **services/** — бизнес-логика. Не знают про FastAPI/Request. Получают репозиторий
  через конструктор (удобно для подмены в тестах).
- **repositories/** — единственное место с SQL по своей таблице. Возвращают
  pydantic-модели из `schemas.py`, а не сырые строки.
- **db/database.py** — соединение (`get_connection`, контекст-менеджер с commit) и
  схема (`init_db`). Путь к БД читается из настроек **на каждый вызов** — это нужно
  для изоляции БД в тестах.
- **config.py** — `Settings` (pydantic-settings, префикс `HUB_`) + `get_settings()`
  с `lru_cache`. Доступ к настройкам — только через `get_settings()`.
- **main.py** — `create_app()` (фабрика) + `lifespan` (инициализация ресурсов на старте).

## Конвенции

- Доступ к настройкам — через `get_settings()`, не создавать `Settings()` напрямую.
- Зависимости (`dependencies.py`) внедряются через `Depends(...)`; в тестах
  переопределяются через `app.dependency_overrides`.
- Пути к `templates/` и `static/` резолвятся от `__file__`, **не** от рабочего
  каталога — сервер можно запускать откуда угодно.
- HTML-формы после POST отвечают `303` редиректом (Post/Redirect/Get).
- Новая сущность = новый набор: schema + таблица в `_SCHEMA` + repository + service +
  роутер. Повторяйте слои, не сокращайте их.

## Команды

```bash
make install     # pip install -e ".[dev]"
make dev         # uvicorn --reload
make test        # pytest
make check       # ruff check + mypy + pytest (перед коммитом)
```

Прямой запуск без make: `uvicorn app.main:app --reload`.

## Тесты

- `tests/conftest.py` даёт фикстуру `client` (TestClient) с **изолированной БД на
  каждый тест**: подменяет `HUB_DATABASE_PATH`, сбрасывает кэш `get_settings`,
  поднимает приложение через `create_app()` (его `lifespan` создаёт схему).
- Тесты ходят через HTTP (`/`, `/api/...`) — это заодно проверяет слои целиком.

### Почему БД в тестах in-memory (важно для скорости)

Фикстура использует **shared-cache in-memory SQLite** (`file:test_<uuid>?mode=memory&cache=shared`),
а не файл на диске. Причина — типовая ловушка производительности тестов:

- Свежий файл SQLite на каждый тест + commit = `fsync` на диск. Это стоит
  **~150–600 ms на тест** (зависит от числа записей), и именно это, а не «медленная
  инициализация БД», обычно тормозит тест-сьют. Сам `CREATE TABLE` — доли мс.
- In-memory убирает диск и fsync целиком: setup падает с сотен мс до единиц мс.
- Изоляция сохраняется: уникальное имя БД на тест; `anchor`-соединение в фикстуре
  держит in-memory базу живой на время теста, а её закрытие — уничтожает базу.

Прод остаётся файловым (durability важна). Если завести файловую БД в тестах
осознанно — для скорости добавьте `PRAGMA synchronous=OFF; PRAGMA journal_mode=MEMORY`.

## Чего не делать

- Не писать SQL вне `repositories/`.
- Не обращаться к `Request`/HTTP из сервисов и репозиториев.
- Не хардкодить пути и секреты — всё через `config.py` / `.env`.
- Не открывать хаб наружу из домашней сети (проброс портов, публичный адрес), пока нет входа и токенов устройств.
